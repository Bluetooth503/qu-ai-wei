# 保护层：不能动的东西

改写的底线一句话：**不新增事实、不删核心事实、不改变责任主体。** 本文件回答三个问题——哪些内容默认不动、怎么核对改写有没有漂、哪些「像 AI 味」的特征其实不该改。

## 一、Protected spans（默认逐字保留）

除非用户明确要求改风格且改动不损害信息，以下一律原样保留：

- 引用原文、命令、接口名、参数名、字段名、配置项
- 日志、报错、代码标识符
- 技术文档里的系统行为主语（「系统会自动重试」的「系统」）
- postmortem / incident / PRD / release note 中的专业术语
- 承载关键事实的抽象句——即使它「有点像 AI」，信息先于风格
- 代码围栏内的程序、注释、文档字符串；路径、URL、版本号、机器字段
- 作者的经历、立场、犹豫、合理转场和有意重复

## 二、信息守恒（白名单的实际内容）

白名单纪律说的是「只动命中的地方」；信息守恒说的是「动的地方也不能改内容」。**改写后的每个实词都要能在原文指出出处；指不出来就是新增，撤销。**

**不许新增**（哪怕只是为了让句子更像人写的）：姓名、机构名、职务、地名；数字、比例、金额、时长、次数；日期、时间、先后顺序；引语、对话、他人说法；出处、链接；因果、动机、心理活动；任何原文没写的细节、场景、案例。

**不许删减**：原文的观点、结论、限定词和让步。「可能提升」改成「提升」是篡改语气强度，不是去 AI 味。把「可能」写成「确定」、把「计划」写成「已经完成」、把「相关」写成「因果」，都算破坏——这些词承载信息，不是修辞。

「把抽象写具体」不是本技能的职责。原文抽象就让它抽象；patterns.md 第 32 条只允许把**原文已有的**具体数据提到概括词的位置，不允许自己造数据。

## 三、事实账本（改写前在心里记，回读时逐项核对）

**1. 数量—对象配对。** 数字和它修饰的对象必须一起留。`两个团队` 不能写成「换过两个团队」；无源论断里的 `40%` 不能删掉后改成「会更快」，`未来十年` 不能改成「未来几年」。删整条可以，改值不行。

**2. 主体—目标配对。** 每个主体和属于它的动作/目标绑定。只属于企业的目标不能顺手并给开发者；删掉 `显著 / 大幅` 时，仍要保留原文实际声称发生了什么。

**3. 谓词的方向、完成态、强度和效果类型。** 这些是关系信息：`性能提升` 不能弱化成「涉及这些方面」；`提升效率` 不能扩写成「节省时间」；`已经改善` 不能写成「涉及」，`完成` 不能写成「开始」。

**4. 同段共现 ≠ 能力关系。** 背景、主题或相邻句共现不等于能力关系。任何 `X 用来做 Y / X 基于 Y / X 处理 Y` 都要能在原文谓词里找到依据；找不到就保留原来的抽象层级，`不能用看似合理的新事实补落点`。

**5. 目的、条件、风险和限制是信息。** `为了解决这一痛点` 可以压成 `为了解决这个问题`，但不能因为没写具体问题就把「解决问题」这一目的删掉。

**6. 抽象层级不得擅自具体化。** `方案` 不能改成 `工具 / 产品`；`目标` 不能改成 `产品`；说某架构的潜力，不能写成「系统基于该架构构建」。

**7. 中英混排。** 英文词按当前句子的实际语义判断，不机械套英文词表。

**8. 作者状态也是信息。** 「接下来检查」不能写成「再检查一轮」；已完成不能改成「可以核对」；作者的猜测仍是猜测。不要替作者变得更自信、更热情或更像公告。

## 四、实证否证表（看着像 AI 味，但不该改）

下表每一行都来自 AI 与人类语料的实测对比：这些特征要么与人类写作无差别，要么方向相反。**它们是硬约束，不是参考**，不据此改文字。

| 特征 | 为什么不改 |
|------|-----------|
| 句长、段落长度不够参差 | 实测与人类无差别。不要为制造节奏调句长或拆段落 |
| 单字虚词偏少（就/很/了） | AI 确实偏少，但方向是补不是删；补虚词无法验收，容易把正式文章改成口语 |
| 反复写全称、少用代词 | 实测人类比 AI 更常重复同一名词 |
| 被动句 | 抽象被动（被认为／被视为）远低于收录门槛 |
| 名词化、长句本身 | 现代汉语书面语的正常写法，人类同样这么用 |
| 正文里的「首先……其次」 | 与人类写作无差别（只管小标题编号） |
| 句内同构排比 | 「提升效率，降低成本，优化体验」人类用得不比 AI 少 |
| 问句、设问、问句小标题 | 正文问句人类远多于 AI，删掉更不像人写 |
| 比喻本身、比喻独立成段 | 人类用得比 AI 多（2.4 倍 / 8 倍） |
| 抽象名词配具体动词 | 「时间替他保管了细节」这类两边都几乎不写 |

规则成立的依据是**触发标记可定位**，不是频率高低。同一特征在不同模型上量级差很大（破折号在某些模型是人类的五倍，另一些几乎不用）。别按「某个模型的味」去套判断，只按触发标记逐句认。

## 五、作者风格文档优先

若同目录下有描述目标风格的文档（写作风格指南、语言特征分析、`语言DNA.md` 一类），先读它，把句长分布、标点习惯、用词偏好作为判断依据。**风格文档与规则冲突时，以风格文档为准**——那是作者真实的写法，不是 AI 痕迹。

## 六、误杀防护的决策顺序

拿不准时按顺序问：

1. 这是 protected span 吗？→ 保留
2. 命中「实证否证表」里的特征吗？→ 保留
3. 改写会改变事实账本里的配对关系吗？→ 不改，或改成不改变关系的写法
4. 这是句式壳还是信息句？→ 只有句式壳才动
5. 删掉后信息点还在吗？→ 不在就不删（`bounded` 下进删除清单交用户点头，`in-place` 下标注不删）
6. 改后的每个实词都能在原文指出出处吗？→ 不能就撤销

「像人」不能把文本改得更假。专业文本可以专业，关键是别模板化、别表演化。
